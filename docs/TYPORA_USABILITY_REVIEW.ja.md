# TyporaとのMarkdown編集ユーザビリティ比較

調査日: 2026-07-19

この文書は、Typoraの公開サポート文書に記載された編集動作を基準に、MarkdaのMarkdown編集体験を比較した結果と実装計画をまとめたものである。MarkdaはVS Codeのカスタムエディターであり、独立アプリであるTyporaのファイル管理やテーマ配布機能をそのまま再現することは目的にしない。比較対象は、Markdown本文を直接編集する際の操作、応答性、編集内容の保全である。

## 比較結果と対応

| 優先度 | 観点 | Typoraで期待される動作 | 修正前の課題 | Markda 0.1.3の対応 |
| --- | --- | --- | --- | --- |
| P0 | 入力応答性 | 入力中にプレビューや文書解析が操作を妨げない | キー入力ごとに全文比較、統計、アウトライン、プレビュー更新が走り、大きな文書で遅延した | CodeMirrorの変更セットを入力フレーム単位で合成し、統計・アウトライン・分割プレビューを遅延更新した |
| P0 | 編集内容の保全 | IME入力、ビュー切替、終了時にも確定済みテキストを失わない | 表セルのIME確定前や送信待ちの末尾差分が残る可能性があった | IME中のコミットを抑止し、非表示化・終了前の最終同期とホスト側の競合検査を追加した |
| P1 | 段落と改行 | Enterで段落、Shift+Enterでハードブレークを作る | ライブ表示でも通常のソース改行になり、表示結果と操作の対応が分かりにくかった | 通常段落だけTypora型の改行を適用し、リスト、引用、見出し、コードではMarkdownの標準操作を維持した |
| P1 | 貼り付け | Webや文書から貼った書式をMarkdownへ自然に変換する | HTMLクリップボードを活用できなかった | 見出し、段落、強調、リンク、画像、リスト、引用、表、コードをMarkdownへ変換するスマート貼り付けを追加した |
| P1 | リンク | 通常クリックで編集し、Ctrl/Cmd+クリックで開く | 表示リンクからソース編集へ移りにくかった | クリックでリンクソースへ移動し、修飾キー付きクリックでリンクを開くようにした |
| P1 | コードブロック | 内容と言語を直接編集し、コードをコピーできる | 表示されたコードブロックはソースへ戻らないと編集できなかった | コード本文の直接編集、IME確定、言語変更、コピーを追加した |
| P1 | 書式操作 | 頻出する段落・インライン書式をショートカットやメニューから使える | 順序付きリスト、引用、コードブロック、取り消し線、書式解除が不足していた | Typoraと対応するコマンドと主要ショートカットを追加した |
| P1 | 表編集 | セル直接編集、Tab移動、行列操作、並べ替え、整列をGUIで行える | 基本操作はあったが、編集中の逐次保存、IME、セル内書式が弱かった | 入力中の安全な同期、Enter/Tab移動、セル内書式ショートカットを追加した |
| P2 | 大きな表 | 表が大きくても文書全体の編集を続けられる | 全セルを編集DOMとして生成し、巨大表で重くなった | 設定上限を超える表は軽量表示にし、ソース編集へ案内するようにした |
| P2 | 数式・図 | 通常の文章編集では追加レンダラーの負荷を負わない | KaTeXとMermaidを初期バンドルで読み込んでいた | 対象要素を初めて描画する時だけ動的に読み込むようにした |

## 実装計画

1. 入力経路から全文処理を外し、差分同期と派生情報の遅延更新を実装する。
2. IME、表セル、ビュー終了時の同期を競合安全にする。
3. 段落改行、スマート貼り付け、リンク、コードブロック、書式コマンドを追加する。
4. 巨大表と数式・図の初期負荷を抑える。
5. 単体テスト、型検査、プロダクションビルド、VSIX内容確認を行う。
6. Marketplaceへ新しいバージョンを公開し、同じソースをGitHubへ反映する。

## 意図的に対象外とした差

- Typora固有の独立ウィンドウ、OSメニュー、ライセンス管理はVS Code拡張の責務外とする。
- PDFなどの追加エクスポート形式、Typoraテーマ互換、スペルチェックは編集の正確性と応答性より優先度が低いため、今回の公開範囲には含めない。
- MarkdaはVS CodeのUndo/Redo、検索、設定、キーバインド、ファイル操作を活用し、同等機能を独自UIで重複実装しない。
